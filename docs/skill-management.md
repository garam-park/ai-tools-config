# 스킬 관리 모델

이 문서는 프로젝트가 제공하는 스킬과 실제 글로벌 설치 상태를 일관되게 설명하기 위한 용어, 판정 기준, 운영 원칙을 정의한다.

## 핵심 원칙

스킬을 하나의 목록으로만 분류하지 않고 다음 세 축을 독립적으로 관리한다.

| 축 | 질문 | 값 |
|----|------|----|
| 소유권 | 누가 원본과 수명 주기를 관리하는가? | 프로젝트 관리 / 외부 / 시스템·플러그인 |
| 배포 정책 | 프로젝트 관리 스킬을 어디에서 사용하게 할 것인가? | 글로벌 / 프로젝트 전용 |
| 설치 상태 | 정책과 실제 설치가 일치하는가? | 설치 완료 / 부분 설치 / 미설치 / 충돌 / 잔존 / 깨짐 |

따라서 “글로벌에 설치 안 된 스킬”은 별도의 스킬 종류가 아니라, 글로벌 배포 정책을 가진 스킬의 현재 설치 상태다.

## 소유권

### 프로젝트 관리 스킬

이 프로젝트가 원본과 변경 이력을 소유하는 스킬이다. 원본은 `skills/<name>/`이며 `SKILL.md`가 있어야 한다.

프로젝트 관리 스킬 목록은 설치 결과나 manifest가 아니라 리포의 원본과 향후 배포 정책을 기준으로 결정한다.

### 외부 글로벌 스킬

사용자 글로벌 경로에 설치되어 있지만 이 프로젝트가 관리하지 않는 개인 스킬이다. 이름이 프로젝트 스킬과 겹치지 않는 정상적인 외부 스킬은 설치 드리프트가 아니다.

외부 스킬을 여러 환경에서 재현해야 한다면 검토 후 프로젝트 관리 스킬로 가져올 수 있다. 가져오기 전에는 프로젝트가 수정, 삭제 또는 자동 교체하지 않는다.

### 시스템·플러그인 스킬

Codex 시스템이나 설치된 플러그인처럼 플랫폼이 제공하고 수명 주기를 관리하는 스킬이다. 프로젝트 관리 스킬과 같은 목록에서 설치 일치 여부를 비교하지 않는다.

## 배포 정책

### 글로벌 배포 스킬

프로젝트 관리 스킬 중 지정된 사용자 글로벌 경로에 설치해야 하는 스킬이다. 현재 설치 대상은 다음 두 경로다.

| 설치 대상 | 사용하는 도구 |
|-----------|---------------|
| `~/.claude/skills/` | Claude Code |
| `~/.agents/skills/` | Codex, GitHub Copilot, OpenCode, 설정된 Hermes Agent |

설치 대상은 여러 개이므로 글로벌 설치 상태는 경로별로 판정한 뒤 집계한다.

### 프로젝트 전용 스킬

프로젝트가 관리하지만 사용자 글로벌 경로에는 설치하지 않는 스킬이다. 특정 프로젝트에서만 필요한 절차나 컨텍스트를 전역 환경에 노출하지 않을 때 사용한다.

현재 `install-skills.sh`는 `skills/*/SKILL.md`가 있는 모든 폴더를 글로벌 설치 대상으로 자동 인식한다. 즉, 현재 구현에서는 모든 프로젝트 관리 스킬이 글로벌 배포 스킬이며 프로젝트 전용 정책을 표현할 수 없다.

프로젝트 전용 스킬을 지원하려면 디렉터리 이름이나 관례로 암묵적으로 제외하지 말고, 리포 수준의 정책 파일 등 명시적인 배포 정책과 설치기·doctor 지원을 먼저 추가한다.

## 설치 상태

설치 상태는 스킬 이름의 존재 여부만이 아니라 각 대상 경로의 실제 항목 종류와 심볼릭 링크 원본을 확인해 판정한다.

| 상태 | 판정 |
|------|------|
| 설치 완료 | 모든 지정 대상에 올바른 프로젝트 원본을 가리키는 심볼릭 링크가 있음 |
| 부분 설치 | 일부 지정 대상만 올바르게 설치됨 |
| 미설치 | 지정 대상 어디에도 설치되지 않음 |
| 설치 충돌 | 같은 이름의 실제 파일·디렉터리 또는 다른 원본을 가리키는 링크가 있음 |
| 잔존 설치 | 더 이상 글로벌 배포 대상이 아닌 프로젝트 관리 링크가 글로벌 경로에 남아 있음 |
| 깨진 설치 | 심볼릭 링크의 원본이 존재하지 않음 |

심볼릭 링크가 올바른 원본을 가리키면 스킬 내용은 리포 작업 트리와 동일하므로 별도의 내용 버전 비교는 필요하지 않다. 복사본이나 다른 원본을 가리키는 항목은 설치 완료로 보지 않는다.

## manifest의 역할

`${XDG_STATE_HOME:-~/.local/state}/ai-tools-config/install-skills.manifest`는 설치기가 성공적으로 만든 관리 링크를 기록한다.

manifest는 다음 실행에서 제거해도 되는 과거 관리 링크를 안전하게 식별하기 위한 소유권 기록이다. 프로젝트가 제공해야 하는 스킬 목록이나 배포 정책의 원본으로 사용하지 않는다.

## 점검과 운영

기본 점검은 변경하지 않는 doctor로 수행한다.

```bash
./install-skills.sh doctor
```

현재 doctor는 다음 항목을 확인한다.

- 프로젝트 원본에 대응하는 링크의 누락
- 다른 원본을 가리키는 링크
- 같은 이름의 실제 파일·디렉터리 충돌
- 프로젝트 원본에서 사라진 stale 링크
- 원본이 없는 dangling 링크

현재 doctor는 정상적인 외부 글로벌 스킬을 별도 목록으로 보여주지 않고, 여러 설치 대상의 상태를 스킬별 `부분 설치`로 집계하지도 않는다. 전체 현황이 필요하면 향후 읽기 전용 `inventory` 기능에서 다음 범주를 함께 출력한다.

- 프로젝트 관리 스킬과 배포 정책
- 대상별 설치 상태와 집계 상태
- 외부 글로벌 스킬
- 시스템·플러그인 스킬 제외 내역

운영 순서는 다음과 같다.

1. 스킬을 추가할 때 소유권과 배포 정책을 먼저 결정한다.
2. 글로벌 배포 스킬은 설치기 실행 후 doctor로 검증한다.
3. 프로젝트 전용 스킬은 글로벌 설치 대상에 포함하지 않는다.
4. 외부 글로벌 스킬은 보존하며, 재현이 필요한 경우에만 프로젝트로 가져온다.
5. stale 또는 충돌 항목은 manifest와 실제 링크 원본을 확인한 뒤 정리한다.

플랫폼별 설치 경로와 설치기의 상세 동작은 [platform-mapping.md](platform-mapping.md)를 참고한다.
