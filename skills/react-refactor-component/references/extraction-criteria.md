# 추출 판단 기준

거대 컴포넌트에서 *무엇을 어디로 뺄지*를 결정하는 기준. 각 항목은 코드를 보고 **예/아니오로 답할 수 있는 신호**와 그에 따른 **판정**으로 되어 있다. "응집도가 높으면 묶는다" 같은 판단 불가능한 격언은 여기에 넣지 않는다.

판정은 셋 중 하나다.

- **추출** — 지금 뺄 수 있다.
- **선행 수정** — 빼기 전에 먼저 고쳐야 한다. 고치지 않고 빼면 버그를 새 파일로 옮기는 것뿐이다.
- **유지** — 빼지 않는다.

---

## A. 상태 → 커스텀 훅

| #  | 신호 (관찰 가능) | 판정 |
| -- | --- | --- |
| A1 | 서로 다른 setter 2개 이상이 **항상 같은 핸들러나 이펙트 안에서 연달아** 호출된다 | 추출 — 그 상태들은 한 훅이다. 동시에 갱신된다는 것은 하나의 관심사라는 뜻이다 |
| A2 | 어떤 상태가 다른 상태·props만으로 계산 가능하다 (setter가 항상 다른 상태의 함수로 호출됨) | **선행 수정** — `useState`를 지우고 계산식으로 바꾼다. 파생 상태를 남긴 채 훅으로 옮기면 동기화 버그를 훅 안에 포장하는 것이다 |
| A3 | 상태 X, X를 저장하는 이펙트, X를 불러오는 로더가 모두 있다 | 추출 — 셋이 한 훅이다. 영속화 경계가 곧 훅 경계다 |
| A4 | `useRef`가 외부 SDK 객체 핸들(뷰어 엔티티, 맵 인스턴스, 소켓, 옵서버)을 들고 있다 | 추출하되 **생성·파괴 코드와 절대 분리하지 않는다.** 핸들과 생명주기는 한 모듈이다 |
| A5 | 추출하려는 훅의 반환값이 6개를 넘고, 그중 일부가 서로를 참조하지 않는다 | **유지** — 두 훅을 하나로 잘못 묶었다. 반환값을 참조 관계로 갈라 다시 나눈다 |
| A6 | 상태가 오직 한 JSX 덩어리 안에서만 읽히고 쓰인다 | 추출 — 상태를 훅으로 올리지 말고 **그 JSX와 함께** 자식 컴포넌트로 내린다 |
| A7 | 상태가 두 개 이상의 형제 컴포넌트에서 읽힌다 | 저장소에 store 계층이 있으면 store로, 없으면 공통 부모의 훅으로. 새 전역 상태 라이브러리를 도입하지 않는다 |

훅 이름은 저장소의 기존 이름을 따른다. 외부 SDK를 다루는 훅에 `use<대상><SDK>` 형태의 선례가 있으면 그대로 쓴다.

## B. 이펙트와 의존성

| #  | 신호 | 판정 |
| -- | --- | --- |
| B1 | 이펙트 본문을 한국어로 설명할 때 "그리고"가 들어간다 (A를 하고 B를 한다) | **선행 수정** — 이펙트를 먼저 둘로 쪼갠다. 쪼개진 뒤에야 각각이 어느 훅에 속하는지 보인다 |
| B2 | 구독·타이머·SDK 엔티티를 만드는데 cleanup이 없다 | **선행 수정** — 분리하면 언마운트·재실행 시점이 바뀌어 숨어 있던 누수가 드러난다 |
| B3 | 의존성 배열이 본문의 실제 참조와 다르다 (빠짐·과다·`eslint-disable`) | **선행 수정** — 틀린 배열은 "지금 우연히 맞는" 코드다. 분리하면 그 우연이 깨진다 |
| B4 | 이펙트가 setState 하는 상태가 같은 이펙트의 의존성 배열에 있다 | **선행 수정** — 순환이다. 추출 대상이 아니라 제거 대상이다 |
| B5 | 이펙트가 `async` 함수를 호출하고 결과로 setState 하는데 취소·마운트 가드가 없다 | **선행 수정** — 경쟁 조건. 분리 후 재현이 더 어려워진다 |
| B6 | 이펙트가 오직 하나의 상태 군집만 읽고 쓴다 | 추출 — 그 군집의 훅 안으로 그대로 따라간다 |

**`react-hooks/exhaustive-deps` 린트 규칙이 꺼져 있는 저장소라면**, B3을 사람이 직접 해야 한다. 전역 설정을 켜면 기존 파일 전체에 경고가 쏟아지므로, 대상 파일에만 파일 단위로 켜서(`/* eslint-disable-next-line */`의 반대 방향) 확인하고, 확인이 끝나면 원래대로 되돌린다. 규칙을 켜는 것 자체를 커밋에 포함하지 않는다.

## C. 순수 로직

| #  | 신호 | 판정 |
| -- | --- | --- |
| C1 | 함수 본문에 `use*` 훅, JSX, DOM, 외부 SDK 호출이 **하나도 없다** | 추출 — 조건 없이 즉시. 가장 싸고 가장 안전한 이동이다 |
| C2 | 컴포넌트 안에 정의됐지만 props·state를 클로저로 읽지 않는다 | 추출 — 컴포넌트 밖으로. 지금은 렌더마다 재생성되고 있다 |
| C3 | 상수 객체·배열·색상표·기본값·프리셋이 모듈 최상단에 있다 | 추출 — 도메인 모듈로. 색상과 기본값은 UI가 아니라 도메인이다 |
| C4 | 타입·인터페이스 선언이 파일 상단에 모여 있고 다른 파일에서도 쓰인다 | 추출 — `*.types.ts`로. 이미 쓰는 형제 모듈이 있으면 그쪽에 합친다 |
| C5 | 계산 함수를 뺐는데 테스트를 안 썼다 | **미완** — 순수 함수 추출의 이득은 테스트 가능해지는 것이다. 같은 커밋에 테스트를 넣는다 |

C1~C4는 **동작을 바꾸지 않는 순수 이동**이다. 이 커밋들의 diff는 "삭제된 줄 ≈ 추가된 줄 + import"여야 한다. 그렇지 않으면 이동하면서 뭔가를 고친 것이다.

## D. 표현 컴포넌트

| #  | 신호 | 판정 |
| -- | --- | --- |
| D1 | JSX 덩어리가 자기 바깥 요소를 참조하지 않고, 필요한 값이 전부 인자로 전달 가능하다 | 추출 |
| D2 | 추출하려니 props가 8개를 넘는다 | **유지** — 경계가 틀렸다. 상태 덩어리를 객체 하나로 넘기거나, 그 덩어리를 훅으로 내려 컴포넌트가 직접 구독하게 한다 |
| D3 | `.map()` 안의 JSX가 인라인 화살표 핸들러를 항목마다 만든다 | 추출 — 항목 컴포넌트로. 핸들러는 항목 id를 닫는 대신 props로 받는다 |
| D4 | 같은 인라인 스타일 객체가 3회 이상 반복된다 | 추출 — 컴포넌트와 함께 움직인다. 저장소에 스타일 컨벤션이 있으면 그것을 따른다 |
| D5 | `<style>` 태그나 전역 CSS 문자열이 JSX 안에 박혀 있다 | 추출 — 그 스타일이 붙는 컴포넌트와 같은 파일로 |
| D6 | 패널·모달·섹션이 자체 열림/닫힘 상태만 쓴다 | 추출 — 상태를 위로 올리지 말고 컴포넌트와 함께 내린다 (A6) |

## E. 명령형 SDK 경계 (지도·3D 뷰어·차트·비디오·캔버스)

React 선언형 모델 바깥에서 동작하는 SDK는 별도 취급한다. 이 경계를 먼저 세우지 않으면 다른 모든 추출이 위험해진다.

| #  | 신호 | 판정 |
| -- | --- | --- |
| E1 | SDK 객체를 만드는 코드와 없애는 코드가 서로 다른 함수·이펙트에 있다 | 추출 — 한 훅으로 모은다. 이것이 누수를 막는 유일한 구조다 |
| E2 | 컴포넌트 JSX나 이벤트 핸들러가 SDK API를 직접 호출한다 | **선행 수정** — 컴포넌트는 상태만 바꾸고, 상태 → SDK 명령 변환은 훅 안에서만 일어나게 한다 |
| E3 | SDK 핸들 배열이 `any[]`다 | **선행 수정** — 타입부터 붙인다. 이 배열의 소유자가 누구인지가 곧 모듈 경계다 |
| E4 | SDK 인스턴스를 전역(`window.*`)에서 읽는다 | 추출하되 그 접근을 훅 한 곳으로 모은다. 전역 접근 자체를 없애는 것은 이 리팩토링의 범위가 아니다 |
| E5 | SDK 준비 완료를 기다리는 폴링·플래그 상태가 있다 | 추출 — 준비 상태 훅 하나로 모으고 나머지 훅이 그것을 구독한다 |

## F. 진입점에 남기는 것

분해가 끝난 뒤 원래 파일에 남아야 하는 것.

- 마운트·언마운트 생명주기 (마이크로 프론트엔드 진입점, `createRoot`, 라우터 연결)
- 최상위 레이아웃 조립 — 어떤 패널이 어디 붙는지
- 훅 호출과 그 반환값을 자식에게 넘기는 배선

남지 말아야 하는 것: 계산, SDK 호출, 도메인 상수, 폼 필드 JSX.

**진입점이 200줄을 넘으면 아직 끝나지 않았다.** 넘는다면 어떤 배선이 사실은 로직인지 다시 본다.

## 경계가 성립하는지 확인하는 질문

추출 후보 하나를 정했으면, 옮기기 전에 다음을 확인한다. 하나라도 걸리면 경계를 다시 그린다.

1. 이 코드가 컴포넌트의 다른 상태·클로저를 **은밀히** 참조하는가?
2. 옮기면 이펙트 실행 순서나 렌더 타이밍이 바뀌는가?
3. 새 모듈이 원래 파일을 다시 import 해야 하는가? (순환 의존)
4. 공개 시그니처가 현재의 모든 호출 지점을 감당하는가?
5. 책임을 한 문장으로 쓸 수 있는가? 두 문장이 필요하면 둘로 쪼갠다.
