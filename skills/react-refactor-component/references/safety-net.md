# 안전망 확보

거대 컴포넌트에는 대개 테스트가 없다. 테스트가 없는 코드를 분해하는 것은 **회귀를 감지할 방법 없이 구조를 바꾸는 것**이다. 이 문서는 착수 전에 무엇을 얼마나 갖출지 정하는 기준이다.

목표는 커버리지 숫자가 아니라 **"이 단계에서 뭔가 깨졌다"를 알려주는 최소한의 장치**다.

---

## 1. 이미 있는 검증 수단부터 센다

새 테스트를 쓰기 전에, 저장소가 이미 제공하는 것을 확인하고 각각이 **무엇을 잡고 무엇을 못 잡는지** 적는다.

| 수단 | 확인 방법 | 잡는 것 | 못 잡는 것 |
| --- | --- | --- | --- |
| 타입 검사 | `tsconfig.json`의 `strict` 값 | 시그니처 불일치, 빠진 인자 | `strict: false`면 `null`/`undefined` 흐름은 못 잡음 |
| 린트 | `.eslintrc*`의 규칙 목록 | 미사용 변수, 명백한 실수 | `react-hooks/exhaustive-deps`가 꺼져 있으면 의존성 오류는 통과 |
| 기존 테스트 | 테스트 러너 설정의 `include` 패턴 | 이미 추출된 모듈의 동작 | 컴포넌트 본체·이펙트 순서·SDK 연동 |
| 빌드 | 빌드 스크립트 | import 경로 오류, 순환 의존 일부 | 런타임 동작 전부 |

이 표를 채우고 나면 **비어 있는 칸이 곧 특성화 테스트가 메워야 할 자리**다.

---

## 2. 특성화 테스트를 쓸 대상 고르기

전부 쓰지 않는다. 다음 두 질문으로 거른다.

1. **깨졌을 때 조용한가?** — 사용자가 즉시 알아차리지 못하는 것부터 쓴다. 화면이 안 뜨는 회귀는 첫 실행에서 바로 드러나므로 테스트가 덜 급하다. 저장된 설정이 안 불러와지는 회귀, 계산값이 미묘하게 틀리는 회귀, 엔티티가 안 지워지는 누수는 조용하다.
2. **이번 분해에서 건드리는가?** — 손대지 않을 영역에는 쓰지 않는다.

우선순위:

1. **순수 계산** — 좌표 변환, 기하 생성, 단위 환산, 유효성 검증. 가장 싸고 가장 확실하다. 추출과 동시에 쓴다.
2. **영속화 왕복** — 저장한 값을 다시 불러오면 같은 값이 나오는가. 스키마 기본값 채움, 마이그레이션, 잘못된 데이터 처리.
3. **상태 전이** — 훅으로 추출할 군집에 대해, 입력 이벤트 순서 → 최종 상태. `@testing-library/react`의 `renderHook`이 있으면 그것으로, 없으면 리듀서 형태로 먼저 뽑아낸 뒤 순수 함수로 테스트한다.
4. **정리(cleanup) 호출** — 언마운트 시 구독 해제·엔티티 제거가 호출되는가. SDK를 가짜 객체로 두고 호출 횟수만 센다.

**쓰지 않는 것**: 렌더 결과의 픽셀·스타일, SDK 내부 동작, 화면 스냅샷 전체. 분해 과정에서 정당하게 바뀌므로 거짓 실패만 만든다.

## 3. 외부 SDK 의존 우회

SDK(지도·3D 뷰어·차트)는 테스트 환경에서 뜨지 않거나 뜨더라도 느리다. 순서대로 시도한다.

1. **경계를 먼저 만든다** — SDK를 쓰는 코드를 얇은 함수 뒤로 밀어내면, 그 바깥은 SDK 없이 테스트된다. 가장 좋은 방법이고 리팩토링 목표와 방향이 같다.
2. **주입한다** — 훅이 SDK 인스턴스를 인자로 받게 하면 테스트에서 가짜를 넘길 수 있다. 전역에서 직접 읽는 것보다 항상 낫다.
3. **모듈을 가짜로 대체한다** — 러너의 모듈 모킹으로 SDK 진입점만 바꾼다. 가짜는 **호출 여부와 인자만** 기록하고 계산은 하지 않는다.
4. **테스트 환경을 바꾸지 않는다** — 한 파일 때문에 러너 환경(jsdom 등)을 바꾸거나 전역 setup을 추가하지 않는다. 다른 테스트에 영향이 간다.

---

## 4. 충분한지 판정

다음 셋을 모두 답할 수 있으면 착수한다.

- 이 단계에서 깨지면 **어떤 명령이 빨간색이 되는가?** 답할 수 없는 단계는 아직 안전망이 없다.
- 그 명령을 **몇 초 안에** 돌릴 수 있는가? 한 단계마다 돌릴 것이므로 느리면 안 돌리게 된다.
- 마지막에 **실제 앱에서 무엇을 눌러 확인할 것인가?** 자동 검증이 못 미치는 영역은 수동 확인 목록으로 남긴다.

안전망이 부족한데 사용자가 진행을 원하면, **거절하지 말고 그 사실을 명시한 뒤 위험이 낮은 단계(순수 이동)까지만 하고 멈춘다.** 상태·이펙트 추출은 안전망 없이 하지 않는다.

---

## 5. 각 단계의 검증 절차

모든 단계에서 같은 순서로 돌린다. 앞 단계가 실패하면 뒤는 돌리지 않는다.

1. 타입 검사
2. 린트 (대상 경로만)
3. 테스트
4. 빌드 (import 경로가 바뀐 단계에서만)
5. 실제 앱에서 해당 화면 확인 (위험 단계에서만)

**순수 이동 단계에는 하나를 더 한다.** diff가 정말 이동인지 확인한다.

```bash
git diff --stat                  # 삭제 줄 수 ≈ 추가 줄 수 + import
git diff -M --find-copies-harder # 이동으로 인식되는지
```

추가된 줄이 눈에 띄게 많으면 옮기면서 뭔가를 고친 것이다. 그 수정을 분리해 별도 커밋으로 빼거나, 최소한 커밋 메시지에 적는다.
