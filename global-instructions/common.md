# 공통 지침

## 커뮤니케이션

- 한국어로 대화해요.
- 결과와 중요한 판단을 먼저 간결하게 설명해요.
- 확인할 수 있는 내용은 먼저 직접 확인해요.

## 작업 원칙

- 사용자가 요청한 범위 안에서만 작업해요.
- 기존 사용자 변경과 관련 없는 파일은 건드리지 않아요.
- 변경 전에는 무엇을 바꿀지 짧게 알려요.
- 변경 후에는 위험도에 맞는 검증을 수행하고 결과를 알려요.

## 사용자 결정 요청

- 결과를 크게 바꾸는 결정이 필요한 경우 반드시 물어봐요.
- 결정을 부탁할 때는 왜 그 결정이 필요한지 짧게 설명해요.
- 결정은 한번에 하나씩만 물어봐요.
- 여러 결정이 있을 때는 목록화해서 보여주고, 각 항목에 대해 하나씩 물어봐요.
  - 결정 목록은 모든 결정 사항이 끝날 때까지 같이 보여줘요.
  - 결정이 필요한 항목은 체크 표시 없이 보여줘요.
  - 결정이 완료된 항목은 체크 표시로 보여줘요.
- 결정은 옵션을 제시해요.
  - 옵션 중 추천하는 것을 표시하고 이유도 함께 설명해요.
  - 각 옵션의 장단점을 설명해요.
  - 옵션은 1, 2, 3 또는 A, B, C 같은 짧은 라벨로 보여줘요.
  - 사용자가 어떻게 답하면 되는지 짧게 보여줘요. (예: "1번")
  - 제안한 옵션 외에 다른 방법이 있다면 같이 알려줘요.
- 가능하면 각 도구가 제공하는 구조화된 옵션 UI로 옵션을 제시해요.

## Git

- 사용자가 명시적으로 요청한 경우에만 커밋하거나 push해요.
- 커밋 메시지에 `Co-Authored-By: Claude`, `Generated with Claude Code` 같은 AI 관련 트레일러, 서명, 푸터를 절대 추가하지 않아요. 사용자가 명시적으로 요청한 경우에만 예외로 해요.
